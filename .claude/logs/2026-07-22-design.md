方針: **1案 = 1D 方式 + 2D 方式の固定ペア**（A=FFD+BSSF、B=BFD+BAF、C=グループ化+BL）。bar と sheet が混在するプロジェクトでも案 ID は横断で1系列。`candidates` は 1〜3 にクランプ（4 以上指定は warning）。パッキングは **stock id ごとに独立**に実行する（parts[].stock が明示バインドのため）。

## 2. データモデルと検証層

### マッピング
- `yaml`（ruamel safe 相当）/ `json` → 素の dict → jsonschema 検証 → dataclass 構築（`from_` は YAML キー `from` からのリネーム）→ 意味検証。
- `.json` 拡張子なら json.load、それ以外は YAML として読む。

### 検証の分担
**層1: スキーマ検証（jsonschema、機械的な形）** — 型・必須キー・enum・数値範囲（`exclusiveMinimum: 0` 等）・追加プロパティ禁止（`additionalProperties: false`）。`parts[].stock` の enum は同一ドキュメントの stocks から注入して自己整合的に検証。

**層2: 意味検証（loader.py に手書き。スキーマで表現できない相互参照・物理条件）**
1. `stocks[].id` / `parts[].id` の重複 → error
2. `parts[].stock` の参照整合（enum と重複するが権威はこちら）→ error
3. **物理的事前チェック**: bar 部材 `length ≤ stock.length − 2·edgeTrim`。sheet 部材 `(l ≤ Lu かつ w ≤ Wu)` または `(rot かつ w ≤ Lu かつ l ≤ Wu)`（`Lu = length − 2·edgeTrim`、`Wu = width − 2·edgeTrim`）。不成立 → error（どの寸法が何 mm 超過かをメッセージに含める）
4. bar 部材: `width` は省略か `stock.width` と同値のみ許容（異なる値 = 挽き割り指定は v1 対象外 → error）。sheet 部材: `width` 必須。
5. feature 境界: groove の `pos ± width/2` が部材内、`depth ≤ stock.thickness`（超過 error、同値は許容＝実質貫通だが v1 では警告のみ）。hole の `x ± dia/2`, `y ± dia/2` が部材内、`depth ≤ thickness`。
6. groove: `end: stopped` なら `from`/`to` 必須かつ `0 ≤ from < to ≤ 走行方向の部材寸法`。`through` に from/to があれば error。
7. `meta.units` は `mm` 固定（他値 error）。`meta.schemaVersion` 不一致は warning。
8. `settings.selectedPlan` は null か生成される案 ID（"A"/"B"/"C"、candidates の範囲内）→ 範囲外は error。
9. bar 部材の `rot` 指定は無意味 → warning で無視。

エラーパス表記は `parts[2].features[0].pos: ...` 形式の日本語メッセージ。

## 3. 1D 割付

### kerf・edgeTrim 消費モデル（厳密定義 — 全実装の規範）

**原理**: edgeTrim = 「生端から edgeTrim mm 以内の材は不健全（荒れ・割れ）」の深さ。**部材の実体はこの不健全域に一切かかってはならない**。kerf（切り粉になる帯）は不健全域・端材域に食い込んでよい。

- 使用可能窓: `[edgeTrim, L − edgeTrim]`、有効長 `U = L − 2·edgeTrim`。
- 配置: `o_1 = edgeTrim`、`o_{i+1} = o_i + len_i + kerf`（隣接部材間に kerf 1回分の帯 `[o_i+len_i, o_i+len_i+kerf)`）。
- **充填可否**: `Σ len_i + (n−1)·kerf ≤ U`。等号成立を許容（境界テスト必須）。
- 先端の捨て切り: 刃は `[edgeTrim − kerf, edgeTrim)` に置く（捨て側が kerf を吸収）。**有効長を追加消費しない**が、カット1回として数える（edgeTrim > 0 のとき）。
- 末尾切り: 最後の部材の右面 `E = o_n + len_n` で切る。刃は `[E, E+kerf)` の端材側に入るため **末尾 kerf は容量条件に含めない**（`E ≤ L − edgeTrim` は容量条件から自動的に成立）。
- **最後のカットが不要になるケース**: `edgeTrim == 0` かつ `E == L`（部材の端面＝生端）に限り末尾カット省略・kerf 消費なし。edgeTrim > 0 のときは生端を部材面に使えないので末尾カットは常に必要。先端も同様（`edgeTrim == 0` なら先端捨て切りなし）。

**カット回数（1本あたり）** = `(1 if edgeTrim>0 else 0) + (n−1) + (1 if not (edgeTrim==0 and E==L) else 0)`。隣接部材の分離カットは両者の面を同時に作る1回。

### qty 展開と決定性
- 全 part を `PartInstance(part, 1..qty)` に展開。
- ソートは常に安定・決定的: 主キー降順長、タイブレークは `(part.id, instance.index)` 昇順。同一入力→同一出力を保証（テスト・watch 差分の前提）。

### アルゴリズム
本数は無制限供給とし、入らなければ新しい原材を開く（＝必要本数の自動決定）。事前チェック(§2-3)により「空の1本にも入らない」は起こらない。

- **案A FFD**: 長さ降順に、開いた順で最初に入る原材へ。なければ新規原材を開いて配置。
- **案B BFD**: 長さ降順に、配置後の残り有効長が最小になる原材へ（タイ: 先に開いた原材）。なければ新規。
- **案C 同種グループ化（group-first FFD）**: 長さ降順（同長は連続）で処理し、原材選択の優先順位を「①同じ長さの部材を既に含み容量のある原材 → ②容量のある最初の原材（FFD）→ ③新規」とする。同長部材が同じ原材に集まり、丸鋸ストッパーでの連続カットに向く。

`fits(bar, len) = used + (kerf if n>0 else 0) + len ≤ U`。各 StockUnit 内の placements は start 昇順で確定。

## 4. 2D 割付（MaxRects）

### kerf / edgeTrim のモデル化（膨張座標系）
古典的な「アイテム膨張」方式を採用する:
- ビン = `(Lu + kerf) × (Wu + kerf)`（`Lu = L−2e`, `Wu = W−2e`）。
- 各部材 = `(l + kerf) × (w + kerf)` に膨張して配置。
- これで「部材間の隙間 ≥ kerf」「使用可能窓の縁には kerf 不要（縁の切り出しカットの刃は不健全域に逃げる ＝ §3 の原理と整合）」が同時に成立する。
- 実座標への復元: 膨張座標 `(x, y)` → 実座標 `(edgeTrim + x, edgeTrim + y)`、実寸 `l × w`。

### MaxRects 本体（Jylänki 準拠）
- 各シートは free rectangle リストを保持。初期値はビン全体1個。
- 配置時: 配置矩形と交差する全 free rect を上下左右最大4分割 → 包含関係で刈り込み（prune）。
- 配置順は**逐次型**（グローバル貪欲は採らない。実装単純性と決定性を優先。品質差は複数案比較で吸収）: 部材列をソートし、1個ずつ「開いているシート群 × free rect × 向き」の全候補から最良スコア位置を選ぶ。どこにも入らなければ新シートを開く。
- `rot: true` の部材は 90° 回転（l↔w）も候補に含める。`rot: false` は原向きのみ。

### 3案の作り方（スコア関数 × ソート順）
| 案 | スコア（小さいほど良い） | 部材ソート | 狙い |
|---|---|---|---|
| A | **BSSF**: min(短辺残り)、タイ: 長辺残り | 面積降順 | 歩留まり定番 |
| B | **BAF**: min(面積残り)、タイ: 短辺残り | 最大辺降順 | 残面積評価を変えた対抗案 |
| C | **BL**: min(配置上端 y)、タイ: min(x) | (width, length) 降順で同幅グループ連続 | 行状レイアウト → カット線が揃い作業性重視 |

タイブレークの最終段は常に (free rect の y, x, シート番号) 昇順で決定的に。

## 5. 木取り図 SVG（plan-X.svg）

- **1ファイル = 1案。案内の全 StockUnit（bar/sheet 混在可）を縦積み**、原材 1 本/枚ごとに 1 パネル。
- **スケール**: px ベース。`scale = 1200 / max(全 StockUnit の length)` を案内で統一（パネル間の寸法比較が視覚的に正しくなる）。`scale` は下限 0.2 上限 4 にクランプ。文字・線幅は px 定数（本文 12px、ヘッダ 16px、stroke 1px）。
- **ヘッダ**（文書先頭のテキストブロック）: `案A ｜ 方式: FFD / MaxRects-BSSF ｜ 歩留まり(全体) 81.3% ｜ 概算費用 ¥7,502 ｜ 必要本数: 1x4-6f×3, pine-18×1 ｜ カット回数 31`。selectedPlan 一致時は `【採用】` を付す。
- **パネル**: タイトル `1x4-6f #1／1820×89×19｜歩留まり 87.2%`。描画要素と色分け:
  - 原材外形: 実寸矩形、stroke 黒。
  - edgeTrim 域: 濃グレー斜線ハッチ（`<pattern>` 定義1個を再利用）。
  - 部材矩形: 淡い木色 `#e8d9b5` 塗り + 黒枠。中央に `① side-0` と寸法 `600`（sheet は `600×200`）。矩形が小さく文字が入らない場合は番号のみ、さらに小さければ外部に引出線（実装者判断）。
  - kerf 帯: 赤系 `#d9534f` 半透明塗り(1D は部材間の縦帯。2D は部材矩形の右・上に kerf 幅の帯を描く)。
  - 端材: 薄グレー塗り。1D は残長を mm 表記。
- **配置番号**: 案内で units→placements（start / (y,x) 昇順）の順に ①②③… を通し採番し `Plan.seq` に保持。加工指示図と連動する。
- viewBox は `0 0 W H` の px。`width`/`height` 属性も同値で付与。

## 6. 加工指示図 SVG（parts/<部材ID>.svg）

- 1部材定義 = 1ファイル（qty 展開はしない。同一形状のため）。
- **ヘッダ**: `side-0（側板0）｜qty 1｜原材: pine-18 (t18)｜1985 × 200`。selectedPlan 設定時のみ `配置: 案A ①③`（Plan.seq からこの part の全インスタンス番号を列挙）。
- **本体（部材ローカル左下原点、SVG では y 反転）**:
  - 外形矩形。bar 部材は `length × stock.width`。
  - **溝**: `across` → x = `pos − width/2 .. pos + width/2` の帯が Y 方向に走る。`through` は全幅、`stopped` は `from..to`（走行方向の座標、止め端は矩形＋端線で可）。`along` は軸を入れ替えて同様。`face: front` は実線＋薄塗り、`face: back` は破線（隠れ線規約）。
  - **丸穴**: 中心 `(x, y)` に径 `dia` の円。貫通は十字センターマーク付き、止め穴は円のみ。
  - **注記**: 溝 `溝 幅7×深6 通し（front）` / 止めは `溝 幅7×深6 止め 120–480（front）`、穴 `Φ4 深8` / `Φ4 貫通`。フィーチャ近傍に引出線付きで配置。重なりが出る場合は部材右側に縦一列リスト＋引出線に退避（衝突判定は「注記バウンディングボックスの重なり」のみの最低限。詳細は実装者判断）。

### チェーン寸法線エンジン（render/dimension.py）
1. **対象点抽出**: X 軸チェーン = `{0, L}` ∪ `{across 溝の中心 pos}` ∪ `{穴の x}`。Y 軸チェーン = `{0, W}` ∪ `{along 溝の中心 pos}` ∪ `{穴の y}`。（溝は中心基準。正本の `pos` 定義が溝中心のため、手描き図面の 248/486/724 表記と一致する。）
2. **ソート・チェーン化**: 許容差 0.01mm でデデュープ → 昇順ソート → 隣接差分を区間値としてチェーン生成。区間値は整数なら整数表記、小数は 1 桁。
3. **配置段数**: X チェーンは部材下側の第1段、**全長寸法は第2段**（さらに外側）。Y チェーンは左側に同様の2段。対象点が `{0, L}` のみの軸は全長寸法1段だけ描く。累進寸法は v1 では描かない（SPECS §8 の未確定事項、オプション化は v2）。
4. **文字被り回避（最低限の規則）**: 区間ラベルは区間中央に配置。推定文字幅（`0.62 × font_size × 文字数` px）が区間描画幅を超える場合、その区間のラベルを寸法線の反対側（下段チェーンなら線の下）にずらし、隣接する狭区間が連続する場合は交互に上下スタガする。それでも重なる場合の追加処理は実装者判断（v1 は上記まで必須）。
5. 寸法線の端点は寸法補助線（部材輪郭から引き出し）＋ 45° ティックまたは矢印（ティック推奨、SVG が単純）。
6. **不変条件（テスト対象）**: 各チェーンの区間合計 == 全長。

## 7. JSON Schema 生成（schema.py）

- **単一ソース**: `build_schema(stock_ids)` が Python の dict リテラルで Draft 2020-12 スキーマを組み立てて返す。各フィールドの `description` は SPECS §4 の定義文を日本語でそのまま埋め込む（例: kerf → 「鋸刃厚（mm）。割付時に切断ごとに消費される。デフォルト 3」）。description 文字列はモジュール定数 `DESCRIPTIONS: dict[str, str]` にまとめ、スキーマ組み立てから参照する。
- **enum 動的注入**: `stock_ids` が非空なら `properties.parts.items.properties.stock` に `"enum": [...]` を注入。空なら `type: string` のみ（enum: [] は全入力を弾くため禁止）。
- **書き出し**: `kidori build` / `watch` の**毎回、検証より先に** `project.schema.json` を project.yaml の隣に書く（ドキュメントが不正でも stocks 部分が読めれば enum を更新し、エディタ支援を維持する。stocks すら読めない場合は enum なしスキーマを書く）。JSON は `ensure_ascii=False, indent=2` で日本語をそのまま出す。
- **モードライン連携**: kidori はユーザの YAML を書き換えない。build 時に先頭行に `# yaml-language-server: $schema=` が無ければ「先頭に `# yaml-language-server: $schema=./project.schema.json` を追記すると補完が有効になります」と1回だけ案内を stderr に出す。
- スキーマは `additionalProperties: false`、bar/sheet の条件分岐（sheet 部材の width 必須等）は JSON Schema では表現しきれないため意味検証層（§2）が担う、と役割分担をコメントで明記。

## 8. summary.json とメトリクス定義

```jsonc
{
  "schemaVersion": "0.2",
  "generatedAt": "2026-07-22T17:30:00+09:00",
  "project": "書棚",
  "selectedPlan": null,
  "plans": [
    {
      "id": "A",
      "method": { "1d": "ffd", "2d": "maxrects-bssf" },
      "stocks": [
        {
          "stockId": "1x4-6f", "kind": "bar", "count": 3,
          "unitPrice": 382, "subtotal": 1146,
          "yield": 0.872, "cutCount": 12,
          "units": [
            { "index": 1,
              "placements": [
                { "part": "shelf-0", "instance": 1, "seq": 3,
                  "start": 5, "length": 600 }
              ],
              "remnant": 180 }
          ]
        }
      ],
      "totals": { "cost": 7502, "costComplete": true,
                  "yield": 0.813, "cutCount": 31,
                  "stockCounts": { "1x4-6f": 3, "pine-18": 1 } }
    }
  ]
}
```

（sheet の placements は `x,y,rotated,length,width`。`remnant` は 1D のみ: `L − edgeTrim − E`。）

**算出定義（厳密）**:
- **歩留まり**: bar = Σ部材長 ÷ (本数 × L)。sheet = Σ部材面積 ÷ (枚数 × L × W)。分母は原材全体（有効長ではない。SPECS §5「原材全体」準拠）。**totals.yield は体積ベース**: Σ(部材の length×width×原材 thickness) ÷ Σ(原材 L×W×t)。bar/sheet 混在でも次元が揃う（bar の部材幅は stock.width）。
- **費用**: `subtotal = count × price`。`totals.cost` は price のある規格の小計和、`costComplete` = 全使用規格に price があるか。price が1つも無ければ `cost: null`。
- **カット回数**:
  - 1D（1本あたり）: §3 の式。
  - 2D（1枚あたり）: `縁の切り出しカット 4回（edgeTrim>0 のとき）+ Σ部材ごとの「使用可能窓の境界に載っていない辺」の数`。窓境界に載る辺は縁カット（edgeTrim>0）または生端容認（edgeTrim==0）で追加カット不要。**共線カットの1パス統合は行わない**（自由配置では保証できないため。ギロチン対応時に再定義する旨をコード内コメントに明記）。この定義は実作業回数の上限近似である。

## 9. CLI 設計

```
kidori build  [PROJECT] [--out DIR] [--no-png] [--png-scale FLOAT]
kidori watch  [PROJECT] [--out DIR] [--no-png] [--png-scale FLOAT] [--interval FLOAT]
kidori select PLAN_ID [PROJECT]        # PLAN_ID: A/B/C、"none" で選択解除
```

- `PROJECT` デフォルト `./project.yaml`。`--out` デフォルトは project と同階層の `out/`（`out/parts/` を含む）。
- **build フロー**: ①raw 読込（可能なら stocks 抽出）→ ②schema 書き出し → ③検証（error なら Issue 一覧を表示し exit 1）→ ④`generate_plans` → ⑤metrics → ⑥SVG 群 → ⑦PNG → ⑧summary.json → ⑨out/ の**管理対象パターン**（`plan-*.svg/png`, `parts/*.svg/png`, `summary.json`）のうち今回生成しなかったものを削除（selectedPlan 切替時の陳腐化ファイル対策。管理外ファイルには触れない）。
- **selectedPlan の扱い**: 設定時は該当案のみアルゴリズム実行・plan-X.svg も1枚のみ・summary.plans も1件。加工指示図は常に全部材分生成し、selectedPlan 時のみヘッダに配置番号（Plan.seq）を表示。null 時は配置番号欄なし（案ごとに番号が異なるため。木取り図側には常に番号を描く）。
- **watch**: 起動時に1回 build → 以後 `--interval`（デフォルト 0.5s）で project ファイルの `(mtime_ns, size)` をポーリング、変化後 200ms のデバウンスで再 build。検証エラーでも watch は継続（エラー表示のみ）。Ctrl-C で終了。追加依存なし。
- **select**: PLAN_ID を検証（candidates 範囲の A/B/C か "none"）→ ruamel.yaml ラウンドトリップで `settings.selectedPlan` のみ更新（コメント・アンカー・キー順保持）→ 続けて build 実行。
- 終了コード: 0 成功 / 1 検証エラー / 2 入出力・引数エラー。メッセージは日本語。

## 10. テスト戦略（pytest）

`tests/` 構成: `test_loader.py`, `test_schema.py`, `test_pack1d.py`, `test_pack2d.py`, `test_metrics.py`, `test_dimension.py`, `test_render.py`, `test_cli.py`, `conftest.py`（fixture: 最小プロジェクト・SPECS §4 の例そのもの）。

必須観点（境界を明示）:
1. **kerf/edgeTrim 境界（1D）**: `Σlen + (n−1)·kerf == U` → 1本に収まる。`+0.1` → 2本目が開く。`kerf=0`、`edgeTrim=0`（末尾カット省略・E==L 許容）、`edgeTrim=0 かつ kerf=0` の全組合せ。
2. **詰め込み可否境界**: bar 部材 `length == L − 2e` は valid、`+0.1` は loader が error。sheet で「回転すれば入る」部材が `rot:false` だと error、`rot:true` だと valid。
3. **1D 3方式**: FFD と BFD が異なる結果を出す既知フィクスチャ。grouped で同長部材が同一 StockUnit に隣接すること。決定性（2回実行で完全一致）。
4. **2D 性質テスト**: 全配置が使用可能窓内。任意の2部材について「x 投影か y 投影が離れており、離間 ≥ kerf」。rot:false 部材が回転していない。必要枚数の自動増加。free rect の不変条件（重複包含なし）。
5. **カット回数**: 1D で n=1, edgeTrim>0 → 2回。n=1, edgeTrim=0, len==L → 0回。n=3 フルケース。2D で窓境界に接する辺の減算、edgeTrim=0/>0 の縁カット有無。
6. **チェーン寸法**: `Σ区間 == 全長`（浮動小数許容差 1e-6）。溝2本＋穴1個の抽出点数と順序。0.01mm 未満の近接点デデュープ。特徴なし部材 → 全長寸法のみ。
7. **メトリクス**: 歩留まり（手計算値と一致）、体積ベース totals.yield（bar+sheet 混在フィクスチャ）、price 欠落時の `cost: null` / `costComplete: false`。
8. **スキーマ**: 生成スキーマ自体のメタ検証（Draft 2020-12 として妥当）、SPECS §4 の例 YAML が pass、未知キー・不正 stock 参照（enum）・負の寸法が fail。stocks 空のとき enum が無いこと。
9. **SVG**: `xml.etree` でパース可能なこと、部材矩形の個数・配置番号テキストの個数が期待値と一致。ゴールデンファイル比較は座標を小数2桁に正規化した上で実施（実装者判断で縮小可）。
10. **CLI/E2E**: tmp_path で build → 期待ファイル一式の存在。select がコメント付き YAML のコメントを保持したまま selectedPlan だけ書き換えること（正本保全の最重要テスト）。selectedPlan 設定後の build で他案ファイルが消えること。watch はデバウンスロジックを関数単位でテスト（ループ自体は E2E 対象外で可）。
