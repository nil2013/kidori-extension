# kidori プロジェクト（エージェント向け導線）

このディレクトリは **kidori**（規格材の木取り図・加工指示図ツール）の作業ディレクトリ。
正本は機械可読なテキスト（`*.kidori.yaml` など）であり、図面（SVG／PNG）はそこから
自動生成される派生物。図を直接編集しないこと。編集するのは常に正本。

## 形式仕様の参照

フィールドの定義・型・必須/任意・既定値・enum は本ファイルに複製しない
（生成時点のスナップショットは陳腐化するため）。対象ファイル用の完全なスキーマは
その場で問い合わせる:

```
kidori schema <ファイル名>
```

## コマンド

| コマンド | 用途 |
| --- | --- |
| `kidori new <ファイル名> [--preset <キー>]...` | 正本ファイル1枚の雛形を生成する（着手の主経路） |
| `kidori init [ディレクトリ] [--with-stocks]` | ディレクトリを初期化する（AGENTS.md・`.gitignore` 等） |
| `kidori build [ファイル] [--out DIR] [--no-png] [--scale N]` | 木取り図・加工指示図・`summary.json` を生成する |
| `kidori watch [ファイル]` | 保存を監視して自動ビルドする |
| `kidori select <A\|B\|C\|X\|null> [ファイル]` | 割付案を採用する（`settings.selectedPlan` を書き換えて再ビルド） |
| `kidori check <ファイル>` | ビルドせずに検証だけを行い、診断を構造化 JSON で出力する |
| `kidori schema <ファイル>` | このファイル用の合成済みスキーマを stdout へ出力する |

## 実行方法

主経路は PATH 上の `kidori` コマンド:

```
kidori <サブコマンド> ...
```

`kidori` が見つからない場合、この環境では CLI のセットアップが未完了である。
**このディレクトリの外を探索しないこと**（`cli.js` の在り処をファイルシステム
から探し回らないこと）。環境変数 `KIDORI_CLI` に CLI 本体へのパスが設定されて
いれば、それで実行できる:

```
node "$KIDORI_CLI" <サブコマンド> ...
```

どちらも使えない場合は、`npm link` の実行または `KIDORI_CLI` の設定をユーザーに依頼すること。

## 出力物

ビルド出力は正本の隣に `<ファイル名>.out/` として生成される
（例: `bookshelf.kidori.yaml` → `bookshelf.out/`）。

- `plan-A.svg` / `plan-B.svg` / `plan-C.svg`（＋厳密探索案 `plan-X.svg`）と同名の `.png`: 木取り図（原材1本／1枚ごとに1面）
- `parts/<部材 id>.svg`（と同名の `.png`）: 加工指示図・基底面（部材1点ごとに1面）
- `parts/<assembly id>-<部材 id>.svg`（と同名の `.png`）: 加工指示図・変種面。取り付けシロ（marks）を持つ構成ごとに出力される。マークの無い形状は基底面のみ、構成の一部だけにマークがある形状は基底面と変種面が併存する
- `schema.json`: このファイル用の合成済みスキーマ（`kidori schema` の出力と同一内容の書き出し）
- `summary.json`: 各案の必要原材本数・概算費用・歩留まり・カット回数と推奨案の機械可読サマリ
- `BUILD-FAILED.txt`: 直近のビルドが失敗したときだけ存在する。あればこのディレクトリの図面は最新の正本を反映していない

出力は正本から再生成される派生物なのでバージョン管理から除外する（`.gitignore` の `*.out/`）。
